# AI 러닝 음악 기능명세

## 1. 기능 개요

**러닝을 마친 사용자가 회고 글만 작성해도 기본 음악이 생성된다. 사진을 함께 올리면, 그날의 러닝 리듬과 사진 분위기를 담은 10초 음악이 사진마다 추가된다.** 러닝 전후의 일상 사진도 넣을 수 있어, 음악이 흐르는 짧은 포토북처럼 하루를 돌아볼 수 있다.

음악은 **러닝 페이스·날씨·회고 감정으로 공통된 템포와 조성을 정하고, 회고 글에 드러난 감정과 여운을 반영**한다. 각 사진의 장면과 분위기에 맞춰 프롬프트를 조정하므로 사진마다 느낌은 달라도 한 번의 러닝을 담은 음악이라는 연결감을 유지한다.

| 항목 | 내용 |
| --- | --- |
| 기능명 | 기록 카드 AI 음악 생성 |
| 목적 | 러닝 기록·회고 글의 감정·그날의 사진을 음악으로 표현해 기록 카드를 다시 감상하는 경험 제공 |
| 대상 사용자 | 러닝을 완료한 사용자 |
| 진입점 | 러닝 종료 후 기록 카드 작성 화면 |
| 핵심 흐름 | **회고 글 작성 → 사진 선택(선택) → 카드 한 번 제출 → 기본 음악 및 사진별 음악 생성** |
| 생성 결과 | 기록 카드당 기본 음악 1개, 사진을 추가하면 사진마다 음악 1개씩 추가 |
| 음악 길이 | **기본 음악 30초, 사진별 음악 10초** |
| 세부 변환 규칙 | `docs/AI_음악_전처리_모듈.md` (BPM·조성·caption) |

## 2. 사용자 흐름

### 2.1 기본 흐름: 회고 글만 작성

1. 사용자가 러닝을 종료한다.
2. 기록 카드에서 회고 글을 작성하고 제출한다.
3. 시스템이 해당 러닝의 평균 페이스와 날씨를 조회한다.
4. AI가 회고 글에 드러난 감정과 여운을 **짧은 분위기 구절**과 감정 방향으로 정리한다.
5. AI가 페이스·날씨·감정 방향을 공통 음악 설정(BPM·조성)으로 변환하고 기본 음악을 생성한다.
6. 기본 음악이 기록 카드에 연결되며, 사용자가 재생할 수 있다.

### 2.2 확장 흐름: 사진 추가

1. 사용자가 **카드를 제출하기 전에** 활동유형(일상·여행·대회)을 입력하고 사진을 선택적으로 추가한다. 사진마다 짧은 캡션을 선택적으로 쓸 수 있다.
2. 사용자가 회고 글과 사진을 **한 번에 제출**한다.
3. AI가 회고 글의 감정과 사진별 장면·분위기를 분석한다.
4. 공통 음악 설정과 회고 분위기를 바탕으로, 사진 분석 결과와 사진 캡션을 더해 각 사진의 프롬프트를 조정한다.
5. 기본 음악 1개(30초)와 사진마다 10초 음악 1개를 생성해 카드·사진에 연결한다.
6. 사용자가 사진을 감상할 때 연결된 음악을 재생한다.

## 3. 기능 요구사항

| ID | 기능 | 수용 기준 |
| --- | --- | --- |
| AI-MUS-01 | 회고 글만으로 기본 음악 생성 | 사진이 0장이어도 제출하면 기본 음악 1개를 만든다. |
| AI-MUS-02 | 카드 공통 음악 설정 | 평균 페이스로 BPM(180/170/160/150)을, 회고 감정 방향 × 날씨 그룹으로 조성을 정한다. 박자 4/4, 연주곡. 페이스 결측 시 160 BPM. 기본·사진별 음악 모두 같은 설정을 쓴다. |
| AI-MUS-03 | 회고 감정 해석 | Qwen3-VL이 회고 글을 텍스트로 입력받아 분위기 구절, 감정 방향(7종), caption용 영어 표현을 만든다. |
| AI-MUS-04 | 기본 음악 반영 | 기본 음악(30초)의 분위기·전개에 회고 분위기를 반영하고 공통 BPM·조성을 유지한다. |
| AI-MUS-05 | 사진 분석 | Qwen3-VL이 사진별 장면·분위기·시간대·음악 단서를 추출한다. 판단할 수 없는 시간대는 `UNKNOWN`으로 둔다. |
| AI-MUS-06 | 사진별 음악 생성 | 각 사진의 장면·음악 단서와 사용자 사진 캡션에 회고 분위기를 함께 반영한 10초 음원 1개를 만든다. |
| AI-MUS-07 | 카드 내 결과 연결 | 기본 음악은 카드에, 사진별 음악은 해당 사진 ID에 연결한다. 사진 순서가 바뀌어도 다른 음원과 뒤섞이지 않는다. |
| AI-MUS-08 | 비동기 생성 상태 | 제출 후 생성 중·완료·실패 상태를 앱에서 구분한다. `생성 중`은 서버 대기열과 모델 실행을 모두 포함한다. |
| AI-MUS-09 | 결과 보관·재생 | 완료된 카드에서 사용 권한이 있는 사용자가 음원을 재생한다. 접근 범위는 카드 공개 정책과 연동한다. |

## 4. 입력 및 출력

| 구분 | 입력 | 출력 |
| --- | --- | --- |
| 기본 음악 | 카드 ID, 러닝 ID, 평균 페이스(초/km), 날씨 코드(WMO 4677), 사용자가 작성한 회고 글 | 회고 해석 결과, 공통 음악 설정, 기본 음악 파일 및 생성 상태 |
| 사진별 음악 | 위 입력 + 활동유형, 사진 ID, 사진, 사용자 사진 캡션(선택) | 사진 분석 결과, 해당 사진의 음악 파일 및 생성 상태 |

> 필드 이름·변환 규칙·caption 조립은 `docs/AI_음악_전처리_모듈.md`를 따른다.

### 회고 감정 해석 기준

회고 **글에 실제로 드러난 감정과 여운을 짧은 구절로 표현**한다.

| 사용자 회고의 예 | 분위기 구절 예시 |
| --- | --- |
| 힘들었지만 끝까지 달려서 뿌듯했다 | 지친 끝에 찾아온 조용한 성취감 |
| 친구와 수다 떨며 달려서 즐거웠다 | 함께 뛰며 느낀 가볍고 들뜬 즐거움 |
| 오늘은 기록이 아쉬웠다 | 아쉬움이 남지만 다시 도전하고 싶은 마음 |
| 별다른 소감 없이 오늘도 5km를 달렸다 | 담담하게 하루의 러닝을 마친 기분 |

- 회고 글에 없는 감정을 러닝 수치나 사진만으로 만들어내지 않는다.
- 여러 감정이 함께 드러나면 하나를 억지로 고르지 않고, 글의 흐름과 마지막 여운을 함께 담는다.
- 분위기 구절은 **한글 한 구절, 30자 이내**를 1차 출력 기준으로 한다. 이 길이는 실제 결과를 확인한 뒤 조정할 수 있다.
- 분위기 구절과 함께 조성 선택용 **감정 방향**을 7종 중 하나로 고른다: 평온·담담함 / 설렘·가벼운 즐거움 / 성취·환희 / 감사·따뜻한 위로 / 아쉬움·그리움 / 고뇌·결연함 / 깊은 슬픔·상실감.
- caption은 영어로 쓰므로, 분위기 구절의 영어 표현도 함께 만든다.
- 회고 글에서 감정을 판단하기 어렵거나 해석에 실패하면 `담담하고 안정적인 분위기`·`평온·담담함`을 기본값으로 사용한다.
- 분석 결과는 **음악 생성용 내부 정보**이며 카드에 사용자의 감정 상태로 표시하지 않는다. 회고 감정은 조성에 영향을 주지만, 페이스에서 정한 BPM을 덮어쓰지는 않는다.

> **내부 JSON 예시** — S3에 저장하는 카드 입력·분석 결과의 개념 예시. 실제 필드명과 분리 저장 여부는 백엔드·AI 데이터 계약에서 확정한다.

```json
{
  "card_id": "card-001",
  "mapping_version": "v1",
  "shared": {
    "bpm": 170,
    "keyscale": "E Major",
    "timesignature": "4",
    "instrumental": true
  },
  "tracks": [
    {
      "type": "BASE",
      "photo_id": null,
      "duration": 30.0,
      "caption": "..."
    },
    {
      "type": "PHOTO",
      "photo_id": "photo-001",
      "duration": 10.0,
      "caption": "..."
    }
  ]
}
```

음악 파일과 사진의 연결 관계는 기록 카드에 저장한다. **사진별 음악은 기본 음악 파일을 편집하는 방식이 아니다.** 같은 카드에서 도출한 공통 설정(BPM·조성·박자)과 회고 분위기를 바탕으로 사진별 음악을 추가 생성한다. 사진 분위기와 회고 감정이 다르면 사진의 질감을 살리면서 회고 글의 정서가 사라지지 않도록 프롬프트를 조합한다.

## 5. 예외 및 수용 기준

| 상황 | 기대 동작 |
| --- | --- |
| 사진 없이 회고 글만 제출 | 회고 글의 분위기를 반영한 기본 음악이 생성되고 기록 카드에서 재생된다. |
| 회고 글에 뚜렷한 감정이 없음 | `담담하고 안정적인 분위기`를 사용해 음악을 생성한다. |
| 회고 감정 해석 실패 | 기본 분위기 구절을 사용해 생성 과정을 계속한다. |
| 사진 여러 장 추가 | 한 번의 카드 요청 안에서 각 사진의 상태·음원 결과를 `photoId`별로 관리한다. |
| 사진별 음악 생성 실패 | 회고 글·사진·기본 음악·정상 생성된 다른 사진의 음악은 유지한다. 부분 실패의 카드 완료 표시는 별도 정책으로 확정한다. |
| 기본 음악 생성 실패 | 회고 글과 카드 작성 내용은 유지되며 실패 상태와 재시도 수단이 제공된다. |
| 음악 생성 대기 중 | 작성 내용과 생성 상태를 볼 수 있다. 대기열에 있더라도 ‘생성 중’ 범주로 표시한다. |

## 6. 시스템 구성

```
[앱] 회고 글 + 활동유형 + 사진·캡션 → 카드 제출
  → [백엔드] 러닝 기록·날씨 조회 → 입력 JSON → 음악 생성 요청 (카드당 1건)
  → [AI] 회고 해석 → 공통 설정 → 사진 분석 → caption 조립 → 음악 생성
  → [백엔드] 완료 알림 확인 → 카드·사진에 음원 연결 → [앱] 재생
```

백엔드는 DB에서 러닝 기록과 날씨를 조회해 입력 JSON을 만든다. AI는 회고 글의 감정과 사진 분위기를 분석하고 음악을 생성한다. **회고 글 해석과 사진 분석은 동일한 Qwen3-VL 모델로 처리하며, 사진이 없는 카드에서는 회고 글 텍스트만 입력한다.** 백엔드는 완료 알림과 결과를 확인한 뒤 카드의 음원 연결 및 상태를 갱신한다. **생성 요청은 카드당 1건**이며, GPU 메모리에 따라 카드 작업 내부의 연산은 순서대로 수행될 수 있다.

## 7. 추가로 확정할 정책

- 기본·사진별 음악의 공통 음악 스타일(장르·악기 구성) 확정
- 날씨 코드를 알 수 없을 때 조성 선택에 쓸 기본 날씨 그룹
- 사진 업로드 가능 개수와 **제출 후** 사진 추가·삭제 시 음악 재생성 방식
- 회고 글 수정 시 분위기를 다시 해석하고 음악을 재생성할지 여부
- 회고 분위기 구절의 길이·표현 기준과 실제 음악에 반영됐는지 확인할 방법
- 사진을 넘길 때 음악을 자동 재생할지, 사용자가 직접 재생할지 여부
- 음악 생성 재시도 횟수, 부분 실패 표시 및 실패 안내 문구
- 생성 중 내부 카드 저장 시점과 기록 탭·피드에 표시할 시점
